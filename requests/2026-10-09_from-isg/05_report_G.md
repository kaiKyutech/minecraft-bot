# 05 G 採集候補の切替

## 結果

Gを実装した。自然地形のスポーン付近からの `inventory.category.log:4` は、同じワールド・開始座標で **改修前0/5 → 改修後5/5**。改修後は5回とも原木8個を実際に回収した。3地点×3目標は **改修前3/9 → 改修後6/9**。改修前に成功した3件の脱落はなかった。

作業ブランチは `isg/05-implement-2026-10-09`、起点は④の最後 `eab3cca`。Gのコミット後、そのままAへ進む。GOAPの計画方式・nearby等の知識・生成ドメインはGでは変更していない。

## 変更

`planner_bot/src/skills/gather.js`：

- 初回は既定の最寄り1候補。失敗位置の数に応じて探索数を広げ、返された候補がすべて回避対象なら倍増する。探索数は最大64。
- `Took to long to decide path to goal!`、その綴り違い、`No path to the goal!` を別候補への切替対象にした。既存のmoveTo時間切れ・掘削失敗等の扱いも維持。
- 失敗位置をボット単位のWeakMapに保持し、GOAPの再計画による次のgather呼出しでも参照する。全素材を合わせて既定32位置、既定3分。古い位置は期限切れ/FIFOで除去。設定しても最大64位置・5分。
- 移動は既定30秒、設定しても最大60秒。試行は既定20回、設定しても最大64回。従来の試行回数の境界のずれも修正した。数・期限の無限指定を受け付けない。
- 中断位置を失敗位置に追加せず、signalを再確認して中断を伝播する。`REPEATED_FAILURE` は再試行せず伝播する。
- カテゴリが選択したブロック種類のキャッシュは変更しない。その種類の別位置を試す。

スキル内部の任意設定は `maxCandidates`、`maxAvoidListSize`、`avoidTtlMs`、`moveTimeoutMs`、既存の `searchSampleSize`・`maxAttempts`。公開APIの名前・結果形は変更していない。

## ライブの条件と復元手順

自然サーバー `../isg/server-natural`（MC25567、RCON25577）だけを使用した。サーバー停止・ポート未使用を確認し、**本体の変更前に** `world` を同じフォルダの `world-05-base` にコピーした。このコピーは残してある。

各試行で、サーバーが停止していることを確認し、絶対パスを検査したうえで `world` だけを削除し、`world-05-base` を `world` にコピーして起動した。試行後はRCONの `save-all` → `stop`、プロセス終了、ポート解放を確認してから次の復元へ進んだ。Javaは独立したHiddenプロセスで起動した。パスワードは記録していない。

毎回新しいボット名を使用し、`clear` で空の持ち物にした。原木5件の改修前は自然スポーン位置を記録し、改修後は対応する同じ座標へtpした。他の9件は④の固定3地点へtpした。**全14組で改修前後の開始座標が完全一致し、開始持ち物が空**であることを検査した。資源のgiveや地形のfill/setblockは使っていない。各目標の中断期限は120秒。

改修前の後半とGのオフライン作業を並行できるよう、採集の旧ソースを `tests/study05/fixtures/gather-before.js` に保存し、改修前試行だけはそれを元のモジュールパスでVMロードした。他の本体モジュールはこの時点では未改修。旧ソースは `eab3cca` と改行を正規化したSHA256が一致することを確認した：`c22c7f175cdca75a5261fe116697e32916e1f9304aa309427072c084fe604c52`。

再実行：

```powershell
./tests/study05/live.ps1 -Phase before
./tests/study05/live.ps1 -Phase G
node tests/study05/summarize-live.cjs before G
```

改修前の再実行は、G以外の本体も未改修のコミットで行うこと。A/B実装後の本体ではGの旧採集だけをロードしても完全な旧版比較にはならない。

保存記録は `tests/study05/live-results.json`。開始座標・空在庫・最終在庫・API結果・候補切替ログ・主な進捗イベントを含む。生記録は `.cache/minecraft-bot/05-study/{before,G}/`、標準テストのログは同フォルダの `G-tests.log`。

## 残る問題

最初の低い地点では、別候補への切替が動いていても移動が30秒ずつ時間切れになり、120秒以内に原木を掘れなかった。例は (17,75,-11) → (17,76,-11) → (17,77,-11)。Gは候補を有限に切り替えるが、すべての地形で到達できることを保証しない。この地点の問題は改修前から残っている。

今回の9件は各1回の対応比較であり、統計的成功率を推定するものではない。④の旧5/9とは初期ワールドが異なるため、その数との単純な比較はしない。今回は同一コピーで3/9 → 6/9を確認した。

GではA/Bや他の案は実装していない。masterへのmerge/push、stable worktree、isg用25568のサーバー、他プロジェクトのコード・設定には触れていない。最後の自然サーバーは全dimensionの保存と正常終了を確認した。
